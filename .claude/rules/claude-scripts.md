## Scripts
- `scripts/<domain>/` at repo root — source only, ignored by chezmoi; binaries compile to `~/.local/bin/`
- `run_onchange_build-scripts.sh.tmpl` — chezmoi rebuilds on source-hash change (`include … | sha256sum`), skips cleanly if compiler missing
- `scripts/claude/secret_guard.nim` is a PreToolUse Bash hook that gates commands **reading content from** sensitive paths — not anything that merely mentions one. Splits the command on shell chaining (`|`, `;`, `&`, backtick, `$(`); for each segment, denies when the leading program is a content-reader (`cat`/`bat`/`rg`/`head`/`cp`/`curl`/`scp`/`openssl`/`jq`/`tar`/etc.) AND the segment mentions a sensitive path. Non-readers (`ls`/`eza`/`stat`/`echo`/`printf`/`git commit`/`git log`/…) pass through regardless of argument contents — that's why `git commit -m "…about .env…"` no longer false-positives. Sensitive paths covered: SSH keys, `.env`/`.envrc`, cloud creds, age/sops, rclone/ngrok/fnox/Copilot tokens, atuin sync key. Known miss: `ls ~/.ssh/ | xargs cat` — per-segment reasoning can't correlate listings with downstream readers (a full shell parser would be needed).
- `scripts/claude/git_add_guard.nim` is a PreToolUse Bash hook that blocks bulk `git add` forms (`-A`, `--all`, `.`, `-u`, `--update`) to force explicit-path staging. Pass-through for `git add <path>`, `git add dir/`, `git add -p`, and non-`git add` commands. Trailing `(\s|$)` on each blocked pattern prevents `--all-hands` / `.bashrc` false-positives.
- `scripts/claude/git_readonly_guard.nim` is a PreToolUse Bash hook scoped via subagent frontmatter to `code-explorer` (NOT global). Splits the command on shell chaining (`|`, `;`, `&`, backtick, `$(`, newline); for each segment that starts with `git`, allows only the read-only verb allowlist (`log`, `diff`, `show`, `blame`, `status`, `reflog`, `shortlog`, `grep`, `ls-files`, `ls-tree`, `cat-file`, `rev-parse`, `rev-list`, `describe`, `name-rev`, `merge-base`); anything else returns `permissionDecision: "deny"`. Non-git segments pass through untouched. Compound commands like `true && git push` are caught because the splitter handles `&&`.
- `scripts/claude/git_confirm_guard.nim` is a global PreToolUse Bash hook (binary `~/.local/bin/git-confirm-guard`) that flags destructive git ops — history rewrite (rebase/filter-branch/filter-repo), any standalone `--force`, hard reset, branch/tag/stash deletion, clean, rm, commit/push, reflog/update-ref/worktree/remote/config destruction — via per-segment regex over shell-chaining splits, env-prefix-stripped (`GIT_SEQUENCE_EDITOR=… git rebase` parses as `git`). Gate-off (no `ALLOW_LLM_DECIDE`) → `permissionDecision: "ask"` naming the flagged segment(s) — the original static behavior. **Gate-on (Layer 2):** the flagged command + recent UNTRUSTED conversation go to `scripts/lib/llm_decide.adjudicate` (prompt `git-confirm-classify`, `strict/pretooluse`) returning allow/ask/deny — so an op the user just authorized can skip the prompt; classifier-unavailable → the static `ask` (never a silent allow on failure). The static detection stays the cheap pre-filter: the model only adjudicates what's already flagged. Per-hook env `GIT_CONFIRM_GUARD_{PROVIDER,MODEL,DECISIONS}`. Wire with NO `if` filter (env-prefixed `GIT_*=… git …` forms would skip a `Bash(git *)` filter). Prompt at `dot_config/llm/prompts/git-confirm-classify.md`. **Layer 3 never-allow tier:** catastrophic (irreversible OR destructive-remote) commands — history rewrite incl. `rebase`, any `--force`, force/`-f`/`+refspec`/`--delete`/`:ref`/`--mirror` push, `reflog expire|delete|clear`, `gc --prune=now`, `reset --hard`, `clean` (≠ `-n`), `checkout --`/`.`/`-f`, `restore`, `switch --discard-changes`, `stash drop|clear`, `branch -f|-M`, `tag -f` — are forced to `{ask,deny}` on gate-on regardless of conversation/config (`isCatastrophic` narrows the enum via the same `writeConstrainedSchema` lockout), so injection can only ever make them stricter, while plain push / `branch -d|-D` / `tag -d` / `commit` / `stash pop` stay auto-allowable on genuine authorization. The detection of `checkout -f`, `branch -f/-M`, `tag -f`, `switch --discard-changes`, `gc --prune=now` is new in Layer 3 — those now also `ask` gate-off (strictly safety-increasing; `branch -M` is common). Every segment is canonicalized by `normalizeSegment` before matching: env-prefix strip + unwrap quoted flags (`"--force"`→`--force`) + re-anchor `git <global-opts> <verb>` → `git <verb>` (so `git -C <dir> reset --hard`, `git -c k=v …`, `--git-dir`/`--work-tree` can't slide a catastrophic verb past the `^git\s+<verb>` patterns — both were red-team-confirmed bypasses). Residual (NOT a full shell parser): quoted args with embedded spaces inside a global opt, `eval`, base64 payloads. Marker hardening for the UNTRUSTED conversation lives in `scripts/lib/llm_decide.buildContext` (shared) — verified to defeat role-prefix injection on both codex and local `Qwen3.6-35B-A3B`.
- `scripts/claude/wezterm_guard.nim` is a global PreToolUse Bash hook (binary `~/.local/bin/wezterm-guard`) that returns `permissionDecision: "ask"` before any `wezterm cli kill-*` invocation (today: `kill-pane`). Rationale: `kill-pane` destroys a pane with no prompt, and without `--pane-id` it kills the *current* pane — i.e. Claude's own shell when run inside WezTerm. Fast-path skips commands not mentioning `wezterm`; splits on shell chaining; per segment, strips leading `KEY=value` env-prefixes (reuses git-confirm-guard's pattern) then asks when the segment's leading program is `wezterm` AND it contains a `cli` token AND a `kill-[a-z]+` token (`kill-[a-z]+` future-proofs for `kill-tab`/`kill-window`). Wired with NO `if` filter (env-prefixed forms would skip a `Bash(wezterm *)` filter). Errs on asking — a `send-text` carrying the literal string `kill-pane` will trip it; acceptable. Runs regardless of whether the `wezterm-cli` skill is loaded. (Note: it only sees the agent's *Bash-tool* calls, not subprocesses — which is why `wezrun` below has no `--kill`.)
- `scripts/claude/inline_script_guard.nim` is a global PreToolUse Bash hook (binary `~/.local/bin/inline-script-guard`, 6th in the Bash chain) that escalates inline Python/Ruby scripts — a second language the shell-parsing guards can't see into. Per shell-chaining segment: when the leading program is `python`/`ruby` (any version suffix) AND the segment carries a `-c`/`-e` flag or a `<<` heredoc, it pipes the *whole command* to `llm` (codex provider, `--schema inline-script --prompt-file inline-script-explain`, self-bounded by `timeout 60`), formats the structured summary (writes/deletes/network/subprocess/credential-read flags + a one-line description), and returns `permissionDecision: "ask"`. The model only explains — never decides; the human always confirms. `llm` failure or timeout still asks, with an explanation-unavailable note — a detected script is never silently allowed. Deliberately over-eager (a false positive costs one extra confirm) and deliberately slow (a codex round-trip — no tight settings.json `timeout`, unlike `sec-guard`). Detection is yes/no, not extraction: the whole command goes to the model. v1 holes: bundled short flags (`-Bc`), scripts piped in (`curl | python`), other interpreters (`node`/`perl`/`php`). Schema at `dot_config/llm/schemas/inline-script.schema.json`, prompt at `dot_config/llm/prompts/inline-script-explain.md`. **`ALLOW_LLM_DECIDE` gate (Layer 2):** with the env var set, this gate-off explain-then-ask flow (unchanged) is replaced by the shared `scripts/lib/llm_decide.adjudicate` — prompt `inline-script-classify`, `strict/pretooluse` schema, recent UNTRUSTED conversation as context — returning allow/ask/deny (the what-it-does summary folded into the decision reason); classifier-unavailable → ask. Per-hook env `INLINE_SCRIPT_GUARD_{PROVIDER,MODEL,DECISIONS}` (`*_DECISIONS=ask,deny` forbids auto-allow structurally).
- `scripts/claude/truncation_guard.nim` is a global PreToolUse Bash hook (binary `~/.local/bin/truncation-guard`) that polices `head`/`tail` truncation of diagnostic output. Fast-path regex `\b(head|tail)\b` skips commands without either word — most Bash calls cost zero. When matched, an in-Nim memo carve-out short-circuits next: the command's leading program (after env-prefix strip, reusing inline-script-guard's `envAssignPrefix`) is checked against `^memo(\s|$)`, and memo invocations pass silently because memo's `--head N` / `--tail N` flags are display-only — the underlying stream is cached and retrievable via `memo show -- <cmd>`, so memo is the non-evasive replacement we *recommend*, not truncation to police. Everything else is classified by the shared `llm_decide.adjudicate` against `strict/pretooluse` (self-bounded by `timeout 30`) which returns the PreToolUse hook decision directly — model is the policy. **Compiled default is now local `lu -P llama -m Qwen3.6-35B-A3B`** (resident always-on model); set `TRUNCATION_GUARD_PROVIDER=codex` to route cloud. Since this guard is always-on, the default switches the *live* classifier dependency to local — if llama-swap is down it fails closed to deny (same fail-closed contract, local dep instead of cloud). Strict-mode null keys (`additionalContext`) are stripped before forwarding. Fails closed: any classifier error / timeout / unparseable response / non-allow-deny-ask decision degrades to deny with a `memo <cmd> --tail N` recommendation. NO regex carve-outs for `tail -f` or `... | sort | head/tail` — the LLM decides those (and got 10/10 on a battery of cargo test / rg / git log / kubectl / pytest / etc. via Qwen3.6-35B-A3B and Qwen3.5-9B llama). Latency: ~1-2 s warm against the resident Qwen3.6-35B-A3B (the now-default local `lu` route); ~5 s if routed to cloud codex/spark. Schema at `dot_config/llm/schemas/strict/pretooluse.schema.json`, prompt at `dot_config/llm/prompts/truncation-classify.md`. Stoppage to remember when reviewing: the deny *reason* is shown to Claude, not the user — Claude reads its own "use memo" recommendation after a block. **Layer 2 refactor:** the `llm` round-trip now goes through the shared `scripts/lib/llm_decide.adjudicate` (always-on, NOT gated on `ALLOW_LLM_DECIDE` — classification is its whole job; `contextTurns=0` so the prompt is unchanged and the kebab `--prompt-file` form is used); `none`→deny is preserved. Per-hook env `TRUNCATION_GUARD_{PROVIDER,MODEL,DECISIONS}`.
- `scripts/claude/llm_local.nim` is a cligen `dispatchMulti` CLI (binary `~/.local/bin/llm-local`) that talks directly to llama-swap's OpenAI-compatible endpoints, skipping the per-call process spawn (~2-5 s) of the upstream `llm` CLI's codex / claude / gemini / pi providers. Five subcommands. `run -m MODEL [--schema NAME] [--promptFile NAME] [-s SYSFILE] [-i IMG ...] [PROMPT...]` is one-shot chat completion; embeds the parsed schema JsonNode verbatim into `response_format.json_schema.schema` with `strict: true`; emits `choices[0].message.content` on stdout so callers parse it the same way they parse `llm --schema X` today. `models [--json]` prints a table of `/v1/models` with `▶` marking entries currently loaded (merged in from `/running`); `--json` dumps the raw payload. `running [--json]` prints per-loaded-model state / backend (parsed from `cmd`'s first token via `extractFilename`) / proxy URL / TTL / name / description. `--baseUrl` is the llama-swap *server root* (default `http://localhost:8000`); `/v1` is appended per-endpoint, admin endpoints (`/running`) sit at root.
  - **Model lifecycle** (added later — llama-swap has no native preload route, only unload + on-demand/config load). `load MODEL...` forces each model resident by proxying a `/health` ping through `GET /upstream/<model>/health`; llama-swap swaps the model in and holds the request open until ready, so the GET is both the trigger and a wait-until-ready barrier (`--timeoutSecs`, default 300, bounds the cold-load wait). Prints `▶ <model> loaded in N.Ns (state: …)`, the state re-read from `/running` (`stateOf` helper). `unload [MODEL...]` stops one or more models via `POST /api/models/unload/<model>` (slashes in model IDs are fine — they're a path segment, no encoding); `--all` instead hits `GET /unload` to stop every process. Bare `unload` with neither errors (no accidental nuke-all). Unload only frees the resident process — models reload on their next request. New `httpPostRaw` helper mirrors `httpGetRaw` (the unload routes are POST; everything else the wrapper does is GET). Round-trip verified live against server v217: a default-group model (`Qwen3.5-9B`) loads in ~5 s and unloads cleanly without evicting any always-on / workhorse / code-completion resident. Endpoint map confirmed against `mostlygeek/llama-swap` `internal/server/server.go` route table — see `.claude/rules/llm-local.md` for the full admin-route inventory.
  - **Prompt roles match the `llm` CLI exactly** (reconciled — earlier versions conflated them): `--promptFile` = the **USER** prompt loaded from a file, joined ahead of positional args + piped stdin; bare name resolves under `~/.config/llm/prompts` with `.md`/`.txt` (cwd-relative tried first, then the install dir). `-s/--systemPromptFile` = the **SYSTEM** prompt (`role:system`), a **literal path only** — no bare-name dir resolution, same as `llm`. So `-s truncation-classify` fails; `-s ~/.config/llm/prompts/truncation-classify.md` works, or use `--promptFile truncation-classify` to feed it as the user message instead (both produce correct guard decisions — verified deny on `swift test | tail`). `--schema` bare names resolve under `~/.config/llm/schemas` with `.json`/`.schema.json`.
  - **Image passthrough** (`-i/--image FILE`, repeatable, short `-i`): when present, the user message `content` becomes an OpenAI content-part array `[{type:text}, {type:image_url, image_url:{url:"data:<mime>;base64,..."}}...]` instead of a plain string. MIME is inferred by extension (`mimeForImage`: png/jpg/jpeg/webp/gif/bmp, else `application/octet-stream`). base64 rides the HTTP body, not argv, so there is no `ARG_MAX` ceiling (a 33 MB image is fine). **Verified working** against llama-server with an mmproj-equipped model (Qwen3.6-27B / 35B-A3B both carry `--mmproj` and correctly described a screenshot). Unlike `llm`'s per-provider gating, llm-local does not check whether the target model is vision-capable — a non-mmproj model just gets an error back from the server. Needs `prompt`-as-positional declared explicitly in dispatchMulti (`positional = "prompt"`) because `image` and `prompt` are both `seq[string]` and cligen can't otherwise tell which is positional.
  - Deliberately NOT ported from `llm`: `--provider` (llm-local *is* the local provider) and `--sandbox` (nono wraps a risky child *process*; llm-local just POSTs to localhost — no subprocess to sandbox, and the localhost request isn't nono's threat model). Also omits `llm`'s anti-persona `CliModeDirective` — the local models don't load the user CLAUDE.md, so there's nothing to suppress.
  - Response decoding via `json_serialization` with typed `Option[T]` per the `feedback_nim_json_serialization` convention; outgoing request body composed with `std/json` because `response_format.json_schema.schema` embeds the caller's parsed JsonNode verbatim, which is awkward with strongly-typed encode. The internal proc is named `runningCmd` (with `cmdName = "running"` in dispatchMulti) to dodge an ambiguity with `std/typedthreads.running` that cligen pulls in. Build stanza requires both `cligen` AND `json_serialization` (mirrors the `claude-statusline` stanza). The guards reach local llama-swap via the **`lu`** CLI (provider `lu` in `llm_decide`), NOT `llm-local` — `llm-local` remains a standalone direct-to-llama-swap tool. See `.claude/rules/llm-local.md` for which backend × endpoint × parameter combinations actually enforce `json_schema strict: true` (short version: `llama-server` + `/v1/chat/completions` + `response_format` is the only fully-enforced path).
- `scripts/wezterm/wezrun.nim` is a cligen CLI (binary `~/.local/bin/wezrun`) that wraps `wezterm cli` for an AI agent: `dispatchMulti` with `exec` (run `<cmd>` in a visible pane → wait via a `__WEZRUN_<nonce>_DONE_%d__` sentinel polled with `get-text` → print last `--lines` of scrollback, default 300, behind a `=== wezrun: <cmd> · pane <id> · exit <n> ===` header → exit with the wrapped command's code) and `capture` (re-print a pane's scrollback). Scoped to the agent's own WezTerm window (`$WEZTERM_PANE`'s `window_id`): with no `--pane-id` it reuses/creates a `claude-run`-titled tab in *that* window; crossing into another window requires an explicit `--pane-id N` (a write into another agent's pane is never implicit). `--fresh`/`--split-right`/`--split-bottom` make a new pane (don't reuse); a `--split-*` pane is left untitled because a split shares its source pane's tab and `set-tab-title` on it would clobber the source pane's tab title. Sends the command with `--no-paste` (so the trailing newline submits). Exit codes follow timeout(1)/env(1): 124 = timed out (`--timeout` is plain int seconds, default 300, `0` = forever), 125 = wezrun couldn't set up (not in a WezTerm pane, `wezterm` missing, pane not found, send-text failed), else the wrapped command's code; `capture` exits 0. No `--kill` (see the wezterm-guard note above) — tear panes down with raw `wezterm cli kill-pane`. `$WEZRUN_TAB_TITLE` overrides the `claude-run` default. Build stanza requires cligen; source-only (chezmoi ignores `scripts/`). Surfaced by the `wezterm-cli` skill (`references/recipes.md` leads with it).
- `scripts/lib/transcript.nim` is a shared Nim module (no binary) for reading Claude Code transcript JSONL. `parseTranscript(path, includeToolNoise=false): seq[Turn]` returns conversation turns in append order, filtering non-conversation noise by default (tool results via `toolUseResult`/`tool_result` blocks; slash-command + stdout user lines `<command-name|command-message|command-args|local-command-stdout>`; `isCompactSummary`; `isSidechain`; `isMeta`; non-user/assistant types). Empty-text (tool-only) turns dropped. Helpers: `lastUserMessage`, `lastUserMessages(n)`, `recentTurns(n)`, `projectSlug` (cwd → `~/.claude/projects/` dir name: `/` and `.` → `-`), `currentTranscriptPath` (newest `*.jsonl` under the slug dir — best-effort current-session), `listTranscripts(projectFilter="", since=none, until=none): seq[TranscriptInfo]` (every `~/.claude/projects/*/*.jsonl` as `{project,sessionId,path,modified,size}`, newest-mtime-first; substring slug filter + inclusive mtime bounds; backs `convo list`). Decodes with `json_serialization` typed `Option[T]` records (`allowUnknownFields = true`); the string-or-array `message.content` union is captured `Option[JsonString]` and re-decoded by shape. Imported by consumers via relative `import ../lib/transcript`. First module under `scripts/lib/`. Tests: `scripts/lib/test_transcript.nim` (`std/unittest`, run with `nim c -r`).
- `scripts/lib/llm_decide.nim` is a shared Nim module (no binary) — the policy-free LLM adjudicator the three LLM-augmentable guards (truncation, git-confirm, inline-script) share. `adjudicate(cmd, promptName, provider="codex", model="", transcriptPath="", contextTurns=0, allowedDecisions=@[], timeoutSecs=30): Option[Decision]` shells out to `llm --provider … --schema strict/pretooluse --prompt-file … [--model …]` under `timeout`, decodes the strict PreToolUse decision, validates it against the allowed set, and returns `none` on any failure — the **caller** maps `none` (truncation→deny, git-confirm/inline→ask); the module makes no policy choice. `allowedDecisions` non-empty narrows the `permissionDecision` enum at runtime into a per-process temp schema under a `0700` `getTempDir()/llm_decide/` dir (one base schema, no per-variant files) so a hook restricted to `{ask,deny}` structurally cannot auto-allow. Conversation context (`contextTurns>0`) is, per turn, `<<<`/`>>>`-neutralized + role-clamped + wrapped in parent-specific provenance markers `<<<USER TURN {id}>>>…<<<END USER TURN {id}>>>` (uuid nonce from the transcript line `id`), then the whole block fence-wrapped as UNTRUSTED data via `scripts/lib/transcript.nim`; `contextTurns=0` sends the bare command (truncation's contract). `emit()` writes the hook envelope from fields (never raw model JSON). **Layer 3 (markers) — verified to defeat the role-prefix injection:** because neutralize mangles any `<<<…>>>` in a turn's TEXT and the begin/end banners are parent-specific with an unguessable id, an embedded `user:` line or forged marker inside a turn body can no longer masquerade as a genuine user turn; the classify prompts accept authorization only from a real `USER TURN` block. Rests on the attacker controlling turn TEXT, not the JSONL role/uuid (Claude Code writes those). Residual: model misjudgment on NON-catastrophic commands — backstopped by the `*_DECISIONS` enum-narrowing and git-confirm's catastrophic never-allow tier. **Provider routing (`runLlm`):** `provider == "lu"` shells the `lu` CLI — `lu -P llama -m <model|Qwen3.6-35B-A3B> --schema <abs> --prompt-file <abs> --no-context-files --ephemeral --max-turns 1` (the `lu` binary honors `--schema` strict on the local llama-swap model, unlike `llm`'s pi/gemini; **abs** schema/prompt paths because lu's bare-name lookup targets lulu-agent's *own* config dir, and `--no-context-files` is mandatory or lu splices the cwd's `CLAUDE.md`/`AGENTS.md` into the classifier prompt — an injection vector). Any other provider goes via `llm` (codex/claude support `--schema`; `llm`'s pi/gemini → `none`→fallback). **All three guards compile-default their classifier to `lu`+`Qwen3.6-35B-A3B`** (local, resident); verified end-to-end — truncation deny/allow, git-confirm gate-ON allow citing the authorizing turn id, and the catastrophic never-allow tier all flow correctly through `lu`'s `--schema`. Tests: `scripts/lib/test_llm_decide.nim` (pure helpers incl. `luArgv` argv shape; the shell-out path isn't unit-tested).
- `scripts/claude/convo.nim` is a `cligen` CLI (binary `~/.local/bin/convo`) over `scripts/lib/transcript.nim`. `dispatchMulti`: `last-user [-n N]` (last N typed user messages, default 1), `recent -n N` (last N interleaved turns, default 5), `all`, `list [--project SUBSTR] [--since DATE] [--until DATE] [--json]` (enumerate transcripts across all projects, newest-first: `mtime  size  sessionId  project`; `--since`/`--until` are ISO or `YYYY-MM-DD` and filter on file mtime, bad value exits 1). Flags: `--path FILE` (override auto-detect; hooks pass payload `transcript_path`), `--json` (structured `[{role,text,timestamp}]` array vs default `role: text`), `--include-tool-results` (`-i`; keep tool-result noise + tool-only turns, dropped by default). Output JSON built with `std/json` (kept separate from the lib's `json_serialization`). Build stanza requires cligen + json_serialization (mirrors `llm-local`). Layer 1 of the transcript-context work; Layer 2 (`ALLOW_LLM_DECIDE` model-as-policy guards, via `scripts/lib/llm_decide.nim`) and `convo list` (via `transcript.listTranscripts`) are both implemented.

## Nim gotchas (this repo)
- Source filenames must be valid Nim identifiers — underscores, not hyphens (`secret_guard.nim`, NOT `secret-guard.nim`). Binary output name (`-o:`) can still use hyphens.
- `std/re` can't compile patterns at `const` time in Nim 2.2+ — use `let` for module-level regex
- `nph` lives in `~/.nimble/bin/`; once zshrc is applied, it's on PATH via `path=(${NIMBLE_DIR:-$HOME/.nimble}/bin $path)`. `nimble shellenv` is project-scoped — NOT for rc-file use.
- `std/md5` is deprecated in Nim 2.2+ (points at the `checksums` nimble pkg). Stdlib version still works — wrap the import in `{.push warning[Deprecated]: off.}` / `{.pop.}` if you don't want the extra dep.
- For Nim CLIs with args/subcommands, use `cligen` (`dispatch` or `dispatchMulti`). Build stanza must `nimble install -y cligen` before `nim c` — see the `notify` stanza in `run_onchange_build-scripts.sh.tmpl` for the `nimble path cligen || nimble install` guard pattern.
