# Claude Code

## Custom skills
- `dot_claude/skills/plan-mode-plans/` — single skill loaded automatically when entering plan mode (per `~/.claude/CLAUDE.md` rule). Covers all four planning variants (single-session, TDD-single, agent-teams, agent-teams + TDD) via a router SKILL.md plus `references/{single-session,tdd-cycles,agent-teams,agent-teams-tdd,audit-prompt-*}.md`. Variant selection is automatic based on task shape (1–2 areas vs 3+; with-TDD vs without). Phase 4.5 plan audit dogfoods `codex:codex-rescue` against the drafted plan before ExitPlanMode; `check-plan` (Nim binary, source `scripts/claude/check_plan.nim`, built into `~/.local/bin/`) is a post-audit sanity gate that verifies required template sections.
- `dot_claude/skills/wezterm-cli/` — drives a running WezTerm GUI/mux session via `wezterm cli` (spawn tabs/windows, split panes, focus, set titles, rename workspaces, send-text, get-text). Router SKILL.md + `references/{commands,recipes}.md`. The "run a command in a shared pane and read the result back" recipe now leads with the **`wezrun`** CLI (`~/.local/bin/wezrun`, source `scripts/wezterm/wezrun.nim` — see `claude-scripts.md`): `wezrun exec -- <cmd>` runs in/creates a `claude-run` pane in the agent's own window, blocks, prints scrollback, propagates the exit code; `wezrun capture` re-reads it. The raw `wezterm cli spawn → send-text --no-paste → poll `__WEZ_DONE_$?__` sentinel → get-text --start-line -N` sequence is kept as the portable fallback (for Codex/Cursor/Aider). Pairs with the global `wezterm-guard` Bash hook (also in `claude-scripts.md`) which confirms before `wezterm cli kill-*` — `wezrun` deliberately has no `--kill` because its internal subprocess would bypass that hook. Adapted from `limiteinductive/agent-skills` (generic `skill.json` layout) into Claude Code's `SKILL.md`-frontmatter format.
- `dot_claude/skills/writing-agent-skills/` — authoring/editing/reviewing Agent Skills per the agentskills.io spec + best practices. Router `SKILL.md` (the shape, frontmatter cheat-sheet, 6 authoring principles, workflow, pattern library, when-to-load reference map) + `references/{specification,best-practices,optimizing-descriptions,evaluating-skills,using-scripts}.md`. Synthesized from six agentskills.io pages (quickstart/specification/best-practices/optimizing-descriptions/evaluating-skills/using-scripts). Dogfoods progressive disclosure (lean body, depth deferred with explicit per-file load triggers). `using-scripts.md` is scrubbed of the upstream Python/JS/Ruby runners and encodes the local language ladder instead (just/bash → Nim → nushell → `go run` for pinned one-off tools; Rust escalation discussed first) plus organizing helpers as `just` recipes. The two structured eval loops (trigger-rate harness in `optimizing-descriptions.md`, with/without-skill output harness in `evaluating-skills.md`) are framed as **opt-in** — offer and confirm before running, never automatic — flagged in the workflow, the reference map, and a callout atop each eval reference. Eval review stays inline (no HTML editor). Portable: deliberately free of chezmoi/setup-specific paths.
- `dot_claude/skills/exact_handoff/` + `dot_claude/skills/exact_pickup/` — the session handoff pair, for surviving a `/clear` (full reset, not compaction). `handoff` writes one self-contained markdown doc capturing goal/status/next-steps/decisions/gotchas/verification; `pickup` reads the newest one back, rebuilds the todo list, and re-verifies against live state before continuing. Both are **skills, not slash commands**, deliberately: only skills deploy cross-agent (see "Cross-agent skill deploy" below), so Codex and `lu` get them too — a `.claude/commands/*.md` would be Claude-only. Beads handling is strictly read-only (snapshot IDs, never mutate/commit/push), matching `plan-mode-plans/references/beads-handoff.md`; `references/beads.md` holds that detail.
  - Both sides share the **`handoff` Nim CLI** (`scripts/handoff/handoff.nim` → `~/.local/bin/handoff`, built by `run_onchange_build-scripts.sh.tmpl`) so the `.handoff/<YYYY-MM-DD-HHMM>-<slug>.md` filename format lives in exactly one place and can't drift between writer and reader. Root dispatcher: `new` (prints a path + creates `.handoff/` — it does **not** write the doc; the agent does), `list` (newest-first table, `--json`), `latest` (path, exit 1 if none), `dir`. `-C`/`--directory` targets another repo. Storage is a flat per-repo gitignored `.handoff/`; the datetime prefix is the only hierarchy.
- Skills are markdown files (`SKILL.md` + bundled `references/`, `scripts/`) with frontmatter (`name`, `description`) plus the body. Loaded by Claude Code automatically when the description matches.

### Cross-agent skill deploy
`run_onchange_deploy-agents-skills.sh.tmpl` rsyncs selected skills out of `~/.claude/skills/` into `~/.agents/skills/` as real copies, which is where Codex and `lu` discover them. **The `SKILLS=(…)` array in that script is the source of truth for the roster — read it rather than trusting any list written elsewhere.** As of 2026-08 it carries `writing-clis`, `handoff`, `pickup`, `writing-rust-code`, `bootstrapping-projects`, `super-code-review`, `plan-mode-plans`, `claude-md-improver`, `decompose-claude-md`, `revise-claude-md`.

- **Adding a skill takes two edits**, not one: append the name to `SKILLS`, AND add a matching `{{ range (glob …/<skill>/**/*.md) }}` hash block above `set -euo pipefail`. The hashes are the only thing that makes chezmoi re-run the script when a skill's *contents* change; without the block the skill deploys once and then silently ossifies. `**/*.md` does match the top-level `SKILL.md` (chezmoi's doublestar lets `**` match zero segments) — no separate pattern needed. Bundled non-`.md` files need their own block (`bootstrapping-projects` has one for `**/*.sh`).
- **Two guards can skip a skill, loudly, on stderr:** a symlinked source (`ast-grep` points back into `~/.agents`, and `rsync --delete` from a dir into itself is data loss), and any name quoted in `~/.agents/.skill-lock.json` (npx-skills territory — see the `reference_agents_skills_territory` memory). Check both before assuming a deploy worked.
- The `exact_` prefix on the chezmoi source dir makes chezmoi prune stale files from `~/.claude/skills/<name>`, which then propagates through `rsync --delete`. It's applied inconsistently — `exact_handoff`/`exact_pickup`/`exact_writing-clis` have it; the rest don't.
- **Slash commands cannot ride this path.** `dot_claude/private_commands/*.md` deploys to `~/.claude/commands/` and is Claude-only by construction. Making a workflow cross-agent means authoring it as a skill, then leaving a **thin command shim** that invokes it — the shim keeps `/name` working and, for commands that took an argument, is the only thing that can still pass one (skills get no `$ARGUMENTS` substitution, so a ported skill needs its own target-resolution step). `decompose-claude-md` and `revise-claude-md` are the worked examples: workflow in `dot_claude/skills/exact_<name>/SKILL.md`, ~15-line shim in `dot_claude/private_commands/private_<name>.md` carrying `allowed-tools: Skill, …`. Edit the skill, never the shim.

### CLAUDE.md memory trio
Three sibling skills, all on the cross-agent roster: `claude-md-improver` (full audit — discovery, git-history scour, categorical findings, routing), `decompose-claude-md` (the refactor — extract to `.claude/rules/`, or split an AGENTS.md spatially into nested per-directory files), `revise-claude-md` (lighter session-end capture). The improver's Phase 7 hands off to decompose.

- **User scope is propose-only across all three.** `~/.claude/CLAUDE.md` and `~/.claude/rules/*.md` get read during discovery (that's what catches project-vs-user conflicts) and get findings reported with full diffs — but no skill applies one unless Alex asked for global/user-level changes that session or approved that specific diff. Approving an audit as a whole does not approve them; they're reported under their own heading for exactly that reason. The rule is stated at `claude-md-improver/SKILL.md` §"This skill writes to memory files" and enforced in its Phase 6, with matching guards in both siblings.
- decompose and revise read rubrics (`decomposition-heuristics.md`, `templates.md`) out of the improver's `references/`. They resolve its root at runtime across `~/.claude/skills`, `~/.agents/skills`, `.claude/skills` — hardcoding the Claude path would dangle on Codex.

## Custom subagents
- `dot_claude/agents/code-explorer.md` — local-codebase research. Sonnet, `tools: Read, Grep, Glob, Bash`, `memory: project`, preloads `ast-grep` skill, frontmatter PreToolUse hook on `Bash` matcher → `git-readonly-guard`. System prompt bans `find | xargs grep`, `| head -N` truncation, training-data recall.
- `dot_claude/agents/github-explorer.md` — GitHub-only remote research (code, issues, PRs, releases, tags, commits). Sonnet, full GitHub MCP read-only allowlist + Read + Bash for `gh` CLI fallback, `memory: user`. System prompt bans `git clone` for exploration; non-GitHub repos get bounced back to `web-explorer`.
- `dot_claude/agents/web-explorer.md` — library/framework/API docs and general web research. Sonnet, `Bash` + `WebFetch` + `WebSearch` (no context7 MCP — uses the `ctx7` CLI via Bash instead), preloads `find-docs` + `firecrawl-{search,scrape,map}` skills, `memory: user`. System prompt mandates `ctx7 library` → `ctx7 docs` first (max 3 calls, optional `--research` retry), bans sequential WebSearch chains and training-data recall.
- Built-in `Explore` is disabled via `permissions.deny: ["Agent(Explore)"]` in `claude-settings.json`. Future broad-exploration delegations match against the three custom agents by description, or fall through to `general-purpose`.
- `scripts/claude/notify.nim` is a multi-event hook (cligen `dispatchMulti` on the first positional arg): `Notification`, `PreToolUse`, `UserPromptSubmit`, `PostToolUse`, `SessionEnd`. **Send:** notifications fire only when Claude is blocked on you — `handleNotification` whitelists `permission_prompt`/`idle_prompt`/`elicitation_dialog` (the `notifyTypes` const — informational `auth_success`/`elicitation_complete`/`elicitation_response` dropped). Backends are pluggable via a module-level `notifiers: array[N, Notifier]` (write a `proc(n: Notification): seq[seq[string]]` returning argv-lists, `@[]` to decline, and append); `apprise` + `grrr` (growlrrr; Zellij/WezTerm click-to-focus via `--execute` focus script, else `--reactivate`) are built-in. **Per-session dismiss:** every grrr notification carries identifier `<agentSlug>-<session_id>`. `agentSlug()` checks documented per-agent env markers first (`LULU_AGENT`→lulu, `CLAUDECODE`→claude-code, `CURSOR_AGENT`, `GEMINI_CLI`, `CODEX_SANDBOX`, `GOOSE_TERMINAL`), then the generic `AGENT`/`AI_AGENT` slug (boolean-guarded), then `luna` (agent-detection background in the `reference_agent_detection_env_vars` memory). `UserPromptSubmit` and `PostToolUse` (matcher = gated set `Bash|Edit|Write|MultiEdit|NotebookEdit|WebFetch|AskUserQuestion`) call `dismissSession` → `grrr clear --delivered <ident>`, clearing ONLY that session's notification (multi-session-safe by construction). PostToolUse covers the unblock paths that do NOT fire `UserPromptSubmit` — answering an AskUserQuestion / accepting a permission both record as `tool_result`s, not prompt submits (transcript-verified); a denial fires no PostToolUse so that case clears on the next typed prompt. Dismiss is guarded by a per-session `/tmp/notify-active-<session>.flag` (written on an actual, non-suppressed send) so it only spawns grrr when something is outstanding. **Permission detail:** the Notification payload carries no tool info, so PreToolUse on the gated tools stashes the pending call (Bash command / `file_path` / url, with a `PendingFreshSeconds` window) to `/tmp/notify-pending-<session>.json`; `handleNotification` names it in the permission body (`Bash: git push origin main`) instead of the generic message. `SessionEnd` removes both scratch files. The per-turn `Stop` "task complete" handler stays removed deliberately (relies on `idle_prompt`; the `Stop` hook in `claude-settings.json` is unwired to match). grrr CLI surface used: `--identifier` on send, `clear --delivered <id>`, `list` (shows delivered notifications with their identifiers — the deterministic test harness).
- `scripts/claude/sec_guard.nim` is a PreToolUse Edit/Write/MultiEdit hook (+ SessionEnd cleanup via cligen `dispatchMulti check|cleanup`). Nim port of the upstream `security-guidance` plugin (which is disabled in `enabledPlugins` in favor of this). 9 rules in a module-level `seq[Rule]`. Uses `permissionDecision: "ask"` by default (`SEC_GUARD_MODE=deny` for legacy blocking behavior). Session-scoped dedup via `~/.claude/security_warnings/<sid>.json`; parent dir created lazily on first warning.
- `scripts/claude/persona_anchor.nim` is a SessionStart + UserPromptSubmit hook (cligen `dispatchMulti session-start|prompt-submit|resolve`) that re-injects a compressed CLAUDE.md recap as `hookSpecificOutput.additionalContext` to combat character/instruction drift. `session-start` always fires (matchers `startup|resume|compact|clear`); `prompt-submit` is counter-gated, fires every Nth call (default N=10) — the counter increments whether or not a body resolves, so a `skip = true` directory can't desynchronize the cadence. State file `~/.claude/persona_anchor/<sid>.json` ({count, last_fired_at}) survives `--resume`/`--continue`; parent dir created lazily on first fire. Knobs: `ENABLE_PERSONA_ANCHOR=0` (kill switch, checked *before* the stdin read), `PERSONA_ANCHOR_FREQUENCY=N` (override default 10), `PERSONA_ANCHOR_FILE=path` (override body source). Edit the markdown to update the recap; no rebuild needed. Inspired by SillyTavern's Author's Note (depth+frequency) pattern.
- `scripts/claude/reward_anchor.nim` is the sibling PreToolUse(`Edit|Write|MultiEdit|Agent`) hook, gated on `permission_mode ∈ {acceptEdits, auto, bypassPermissions}`, counter N=8; `reset` zeroes the counter on UserPromptSubmit. Its body is a template — `<MODE>` / `<COUNT>` substituted at emit time. Knobs mirror persona's (`ENABLE_REWARD_ANCHOR`, `REWARD_ANCHOR_FREQUENCY`, `REWARD_ANCHOR_FILE`).
- **Which body each anchor injects** is decided by `resolveAnchor` in `scripts/lib/anchor.nim` from the current working directory (hook payload `cwd`, else `getCurrentDir()`) and the host coding agent, against a TOML manifest — `~/.claude/anchors/anchors.toml`, a symlink to `~/Code/lulu-prompts/Prompts/Agents/anchors.toml`, where all the Luna-specific policy and prose live (this repo stays free of both). See `claude-scripts.md` for the resolution order and rule semantics, and **lulu-prompts `Prompts/Agents/CLAUDE.md` → "Anchor manifest" for the authoring workflow** (how to add a per-directory / per-agent variant — no rebuild needed, it's edited next to the manifest). The agent is named explicitly by a `--agent <slug>` flag on each hook command (`--agent claude-code` in `claude-settings.json`, `--agent codex` in `~/.codex/hooks.json`) because each agent's hook config is agent-specific by construction; `agent_env.agentSlug()` is only the fallback, and it can't be trusted for Codex (`CODEX_SANDBOX` is set only when the sandbox is active). Both binaries also expose `resolve [--agent S] [--cwd P]`, which prints the path that *would* be injected and exits 1 when nothing resolves — the seam for hosts with no hook system: `lu --system-prompt-file "$(persona-anchor resolve --agent lu)"`.
- **Codex persona gap (open):** `~/.codex/hooks.json` runs `persona-anchor` but no `persona/codex.md` variant exists yet, so Codex still receives the Claude-flavored catch-all body. `reward-anchor` is deliberately not wired into Codex at all.

## Claude Code hooks
- Global settings at `~/.claude/settings.json` — NOT chezmoi-managed
- `PreToolUse` + `matcher:"Bash"` hook reads `tool_input.command` as JSON on stdin
- Deny JSON: `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}`
- **Gotcha:** inline test payloads containing sensitive strings (e.g. `echo '{"tool_input":{"command":"cat ~/.ssh/id_rsa"}}' | hook`) trip the hook because YOUR bash command contains the sensitive path. Put test payloads in a `/tmp/*.sh` script and `bash` it.
- After editing settings.json, open `/hooks` or start a new session so the watcher picks up changes
- Non-Bash events work too: `Stop`, `Notification`, `SubagentStop`, etc. — each is its own top-level key in `hooks`. `PreToolUse` accepts `matcher: "<tool name>"` for any tool (e.g. `"AskUserQuestion"`), not just `"Bash"`. Scope narrowly — without a matcher, the hook fires on every tool invocation.
- **Gotcha:** `/plugin` disable rewrites `claude-settings.json` and can strip unrelated hook entries. Disabling `security-guidance` via `/plugin` also removed my Stop/Notification/AskUserQuestion notify hooks. Always `git diff claude-settings.json` after any `/plugin` action and restore anything that got wiped.
- `PreToolUse` decision output in `hookSpecificOutput`: `permissionDecision: "allow" | "deny" | "ask"` + `permissionDecisionReason`. Plus `updatedInput: { ... }` to rewrite the tool call entirely (e.g. rewrite `grep` → `rg`). Use `"ask"` for advisory/reminder hooks; `"deny"` is a hard block that can even prevent writing documentation *about* the hook's own trigger patterns.
- Per-hook settings.json fields: `if: "Edit(*.ts)"` (permission-rule-syntax filter for tool+path; tool name appears to be required, alternation like `Edit|Write(*.py)` unverified), `statusMessage: "..."` (custom spinner text), `timeout: 5` (override the 600 s default for hot-path hooks that should never legitimately hang).
